# Блок-схемы алгоритма ГОСТ 28147-89

## Для отчёта

`gost28147-89.puml` -- сводная блок-схема базового преобразования блока.
Расписание раундовых ключей и функция `f` развёрнуты внутри цикла раундов,
поэтому схема самодостаточна и занимает одну страницу. Режимы работы
(простая замена, гаммирование, гаммирование с обратной связью, выработка
имитовставки) отличаются только обвязкой вокруг этого преобразования и
описаны в тексте отчёта.

## Подробные схемы (по желанию)

Разбиение того же алгоритма по уровням. В отчёт не обязательны, полезны
при защите, если попросят детализировать отдельный этап.

| Файл | Содержание |
| --- | --- |
| `01-f.puml` | Функция преобразования `f` |
| `02-subkey.puml` | Расписание раундовых ключей |
| `03-encrypt-block.puml` | Базовое преобразование блока (циклы 32-З и 32-Р) |
| `04-mac-block.puml` | Цикл выработки имитовставки (16-З) |
| `05-ecb.puml` | Режим простой замены |
| `06-ctr.puml` | Режим гаммирования |
| `07-cfm.puml` | Режим гаммирования с обратной связью |
| `08-mac.puml` | Выработка имитовставки |

## Рендеринг

Только сводная схема:

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img gost28147-89.puml
```

Все схемы сразу:

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img *.puml
```

`-tsvg` предпочтительнее `-tpng`: Typst поддерживает SVG, и в PDF схема
останется векторной.

## Включение в отчёт

```typst
#figure(
  caption: [Блок-схема базового преобразования блока],
  image(height: 85%, "img/gost28147-89.svg"),
) <scheme>
```

Схема вытянута по вертикали (соотношение примерно 1:2), поэтому размер
удобнее задавать через `height`, а не `width`.

## Замечания по нотации

- `xor` -- сложение по модулю 2. Символ `⊕` не используется: в стандартных
  шрифтах headless-рендера PlantUML он отсутствует и выводится пустым
  прямоугольником.
- `N1`, `N2` -- половины обрабатываемого блока, `N1` подаётся на вход `f`.
- Перестановка половин в конце цикла эквивалентна 32-му раунду без обмена,
  как этот шаг описан в тексте стандарта.
- Шестнадцатеричные константы гаммирования приведены явно, чтобы схема не
  зависела от того, какая из них названа `C1`, а какая `C2`: в тексте
  стандарта и в реализациях эти имена нередко расходятся.
