# Блок-схемы криптосистемы Рабина

## Для отчёта

`rabin.puml` -- сводная блок-схема зашифрования и расшифрования сообщения.
Разбиение на блоки, формат блока, извлечение корней по китайской теореме об
остатках, выбор корня по избыточности и снятие дополнения показаны одной
схемой с ветвлением по направлению, поэтому схема самодостаточна и занимает
одну страницу. Генерация ключей описана в тексте отчёта.

Отрендеренная версия лежит в `../img/block_scheme.svg` и включается в
приложение Б.

## Подробные схемы (по желанию)

Разбиение того же алгоритма по уровням. В отчёт не обязательны, полезны при
защите, если попросят детализировать отдельный этап.

| Файл | Содержание |
| --- | --- |
| `01-keygen.puml` | Генерация простых `p`, `q` вида `4t + 3` и обратных элементов |
| `02-encrypt-block.puml` | Формат блока (данные, избыточность, маркер) и `c = m^2 mod n` |
| `03-decrypt-block.puml` | Четыре корня по КТО и выбор истинного по избыточности |

## Рендеринг

Только сводная схема (выход переименовывается в `block_scheme.svg`):

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img rabin.puml
mv ../img/rabin.svg ../img/block_scheme.svg
```

Все схемы сразу:

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img *.puml
```

`-tsvg` предпочтительнее `-tpng`: Typst поддерживает SVG, и в PDF схема
останется векторной.

## Включение в отчёт

```typst
#figure(
  caption: [Блок-схема алгоритма],
  image(height: 82%, "img/block_scheme.svg"),
) <block_scheme>
```

Соотношение сторон схемы -- примерно 1:1,5, поэтому по ширине страницы она
вместе с заголовком приложения не помещается, и размер задаётся через
`height`.

## Замечания по нотации

- `k` -- длина модуля `n` в байтах (384 для 3072-битного `n`), `R = 16` --
  длина избыточности, `D = k - R - 2 = 366` -- число байт данных в блоке.
- Числа записываются байтами от младшего к старшему (little-endian), поэтому
  «старший байт» блока -- последний, с индексом `k - 2`.
- `80`, `01`, `00` -- значения байтов в шестнадцатеричной записи.
- `yp = p^(q-2) mod q` и `yq = q^(p-2) mod p` -- обратные элементы по малой
  теореме Ферма; вычисляются один раз при создании закрытого ключа.
- `(t1 - t2) mod n` в реализации вычисляется как
  `(t1 mod n + n - t2 mod n) mod n`, потому что `BigUint` не хранит
  отрицательных чисел.
- `<>` -- «не равно», `·` -- умножение. Символы `≠` и `⊕` не используются по
  той же причине, что и в lab2: в шрифтах headless-рендера PlantUML их может
  не оказаться.
