# Блок-схема криптосистемы Мак-Элиса на кодах QC-MDPC

## Для отчёта

`mceliece.puml` -- сводная блок-схема зашифрования и расшифрования сообщения.
Дополнение и разбиение на блоки, выбор вектора ошибок, зашифрование
`c0 = m·A + e0`, `c1 = m·B + e1`, синдром, декодер с переворотом битов
(счётчики `upc0`/`upc1`, порог BIKE, лимит итераций, проверка веса),
умножение на `a^-1`, контроль `c1 + e1 = m·B` и снятие дополнения показаны
одной схемой с ветвлением по направлению. Генерация ключей описана в тексте
отчёта.

Отрендеренная версия лежит в `../img/block_scheme.svg` и включается в
приложение Б.

## Рендеринг

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img mceliece.puml
mv ../img/mceliece.svg ../img/block_scheme.svg
```

## Замечания по нотации

- `r`, `d`, `t` -- длина блока, число единиц в каждом из `h0`, `h1` и число
  ошибок; `k = floor(r / 8)` -- байт текста в блоке, `h = ceil(r / 8)` -- байт
  в половине шифроблока.
- `x^p·h0` -- циклический сдвиг `h0` на `p` позиций; `e0'`, `e1'` -- ошибка,
  найденная декодером.
- Биты байта нумеруются от младшего к старшему.
- `a^-1`, `<>`, `x^r` записаны ASCII: в шрифтах headless-рендера PlantUML
  надстрочных символов и `≠` может не оказаться. Двойной дефис в тексте
  блоков не используется: PlantUML понимает `--текст--` как зачёркивание.

## Выводы программы

Рисунки 2.1–2.5 -- реальные сеансы работы программы, сохранённые в
`../output/*.txt` (введённые строки вставлены в текст так, как их показывает
терминал). Они сняты скриптом, который запускает `target/release/lab4.exe` и
подаёт ввод через stdin. Шифротекст в текстовом режиме занимает 6164
шестнадцатеричные цифры, поэтому его середина в выводах заменена пометкой
`[опущено символов: N]`. При повторном снятии ключи и шифротексты будут
другими, и числа, упомянутые в тексте разделов 2.1–2.5 (веса, время, число
различающихся бит, изменённый байт), нужно будет обновить.
