# Блок-схемы алгоритма BelT (СТБ 34.101.31-2011)

## Для отчёта

`belt.puml` -- сводная блок-схема базового преобразования блока. Такт
преобразования и расписание подключей развёрнуты внутри цикла, зашифрование и
расшифрование показаны одной схемой с ветвлением по режиму, поэтому схема
самодостаточна и занимает одну страницу. Режимы работы (простая замена,
сцепление блоков, счётчик, гаммирование с обратной связью, выработка
имитовставки) отличаются только обвязкой вокруг этого преобразования и описаны
в тексте отчёта.

Отрендеренная версия лежит в `../img/block_scheme.svg` и включается в
приложение Б.

## Подробные схемы (по желанию)

Разбиение того же алгоритма по уровням. В отчёт не обязательны, полезны при
защите, если попросят детализировать отдельный этап.

| Файл | Содержание |
| --- | --- |
| `01-g.puml` | Функция `G_r`: замена байтов по таблице `H` и циклический сдвиг |
| `02-ecb.puml` | Режим простой замены с кражей шифртекста |
| `03-cbc.puml` | Режим сцепления блоков |
| `04-ctr.puml` | Режим счётчика |
| `05-cfm.puml` | Режим гаммирования с обратной связью |
| `06-mac.puml` | Выработка имитовставки |

## Рендеринг

Только сводная схема:

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img belt.puml
```

Все схемы сразу:

```
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../img *.puml
```

`-tsvg` предпочтительнее `-tpng`: Typst поддерживает SVG, и в PDF схема
останется векторной.

## Включение в отчёт

```typst
#figure(
  caption: [Блок-схема алгоритма],
  image(width: 100%, "img/block_scheme.svg"),
) <block_scheme>
```

Соотношение сторон схемы -- примерно 1:1,3, поэтому по ширине страницы она
помещается целиком и размер задаётся через `width`.

## Замечания по нотации

- `xor` -- сложение по модулю 2. Символ `⊕` не используется: в стандартных
  шрифтах headless-рендера PlantUML он отсутствует и выводится пустым
  прямоугольником. По той же причине `phi1`, `phi2` вместо греческих букв.
- `a`, `b`, `c`, `d` -- четыре 32-битных слова обрабатываемого блока в том
  порядке, в каком они лежат в байтовой строке.
- `K[m]` -- слово ключа с номером `((m - 1) mod 8) + 1`: расписание ключей
  тривиально, за 8 тактов по 7 обращений каждое слово используется семь раз.
- Индексы подключей внутри такта при расшифровании идут в обратном порядке
  (`7i`, `7i-1`, ..., `7i-6`), а сами такты -- от восьмого к первому.
- Сложение и вычитание слов -- по модулю `2^32`, в реализации это
  `wrapping_add` и `wrapping_sub`.
- Финальная перестановка слов различается для зашифрования (`b || d || a || c`)
  и расшифрования (`c || a || d || b`).
